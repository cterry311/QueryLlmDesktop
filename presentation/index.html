Query

A desktop interface for Large Language Models

Conversational chat · Autonomous agents · Local-first

What is Query?

Query is an Electron desktop application for interacting with Large Language Models.

It supports both simple conversational chat and fully autonomous agentic workflows, with a focus on flexibility and privacy.

  • Bring your own API keys
  • Your data stays on your machine
  • Works with cloud or local models
The Idea

One desktop client that can talk to any OpenAI-compatible model and, when you let it, act on its own to get things done.

What it can do

Multi-model support

Connect to OpenRouter, Ollama, Docker Model Runner, or any OpenAI-compatible endpoint.

Agentic workflows

Models can plan, act, and observe in a think→act→observe loop to complete multi-step tasks.

Persistent memory

A vector database gives the model long-term recall across conversations.

Local file access

With explicit user permission, agents can read and write files on the host machine.

Conversation history

Every conversation is stored in a local SQLite database — nothing leaves your machine.

Agent tools

When operating in agent mode, the model is given access to a set of tools it can invoke autonomously:

Web searchSearch the web and retrieve results via LangSearch
HTTP requestsMake arbitrary web requests to any endpoint
Code executionRun code inside an isolated Docker sandbox
Memory recall / creationQuery the vector database for relevant past context
File read / writeTouch local files — only with explicit user permission
Powershell CommandsRun Command with user permission

Key technical concepts

Agentic loop

A think → act → observe cycle. The model decides which tool to call, the backend executes it, and the result is fed back as the next observation.

Tool use / function calling

The backend exposes tools to the model through the OpenAI tool-calling schema, then routes each call to a safe handler.

Sandboxed execution

Generated code never runs on the host. It runs inside a locked-down Docker container with no network access.

Vector embeddings

Past conversation chunks are embedded and stored in LanceDB so the model can semantically recall context, not just keyword-match it.

Local-first design

Conversation history, memory, and keys all live on the user's machine. Nothing is mirrored to a third-party server.

Provider abstraction

A single OpenAI-compatible client layer means swapping between OpenRouter, Ollama, or a custom endpoint is a config change.
